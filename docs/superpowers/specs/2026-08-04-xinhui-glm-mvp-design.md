# 心绘 GLM 前端 MVP 设计

## 目标

在空白工作区中构建一个可本地运行、可用于答辩演示、可继续扩展的心理数据可视化与支持平台。产品叙事保留 ChatGLM2-6B、LoRA、Prompt、LangChain 与心理知识图谱；DeepSeek 仅作为演示阶段可替换的在线模型 Provider。所有统计数据明确标注为演示数据，所有咨询输出坚持非诊断性边界。

## 技术路线

- 前端：Vue 3、TypeScript、Vite、Vue Router、Pinia、Apache ECharts。
- 动效：CSS transitions/keyframes 与 Vue Transition，避免引入只服务少量动画的重型依赖。
- 图标：Lucide Vue。
- 后端：Express + TypeScript，以 `/api/chat` 暴露同源代理。
- 模型：服务端使用 Anthropic Messages 兼容协议，读取 `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_MODEL`。
- 开发：一个 `npm run dev` 同时启动 Vite 与 Express；生产构建分别校验客户端和服务端。
- 测试：Vitest 覆盖安全分类、mock 回复、筛选逻辑和服务端回退；浏览器验收覆盖桌面与移动端关键路径。

## 页面与组件

全站采用固定顶部导航和全宽内容带，不制作营销式落地页。首页第一屏直接呈现品牌、核心入口、指标和动态图表预览，并露出下一屏内容。

- 首页：项目价值、识别到干预闭环、四项演示指标、陈列馆和诊疗室入口。
- 陈列馆：统一筛选栏、趋势折线图、中国风险地图、人群雷达图、情绪堆叠柱状图、关键词云和地区详情。
- 数据库：数据来源说明、处理流程、四维标签、可筛选演示表格和 API 能力。
- 诊疗室：桌面三栏、移动单列；包含会话列表、聊天区、输入区、在线状态、分析面板和危机提示。
- 技术亮点：ChatGLM2-6B、LoRA、Prompt、LangChain、知识图谱及训练数据策略。
- 应用场景：学校、医院辅助预筛查、社区和咨询机构，以及未来扩展方向。

组件按职责拆分为布局、通用控件、图表、咨询、页面、状态、服务和 mock 数据。图表组件只负责 ECharts 生命周期和渲染；筛选及数据派生集中在 store/service，避免页面组件内堆叠业务逻辑。

## 视觉与交互

视觉基调为温和可信的数据工作台：浅暖灰背景、深墨色正文、蓝绿色主色，珊瑚色与金色用于风险和重点信息。卡片圆角不超过 8px，不使用大面积渐变、装饰光球、过量玻璃拟态或层层嵌套卡片。

图表使用统一的非彩虹色板、清晰 tooltip、稳定尺寸和空状态。微交互控制在 120-220ms，模块入场 240-360ms，页面转场 280-450ms，图表动画 600-1000ms。系统开启 `prefers-reduced-motion` 时关闭位移和循环动画。移动端折叠导航、图表单列、咨询分析面板下移，所有控件保持可触达和无文本溢出。

## 数据流

陈列馆筛选条件写入 Pinia。store 根据年份、地区、人群和情绪类型派生统一上下文，各图表消费同一份上下文并平滑更新。点击地图省份会更新地区详情和相关图表；跳转诊疗室时通过 query 参数传递地区、人群和情绪类型，咨询页将其转化为模型上下文。

诊疗室提交消息后立即写入用户消息并进入 loading。前端先做快速危机词检测，以便无延迟展示安全提示；后端再次执行权威安全检测。普通消息请求 `/api/chat`：在线模型成功时解析为统一结构，缺少配置、超时、协议错误或上游失败时返回 mock 结构并标记 `mode: mock`。前端只消费统一回复类型，不关心 Provider 细节。

## 安全与错误处理

- 真实密钥只保存在本地 `.env`，`.env` 必须被 `.gitignore` 忽略；`.env.example` 只含空值和说明。
- 浏览器不得直接调用上游模型，也不得获得真实密钥。
- 危机表达优先返回简短安全提示，建议联系当地急救、医院急诊、可信赖的人或专业危机资源，不生成复杂分析。
- 普通回复采用共情、情绪识别、可能压力来源、具体建议和专业帮助提示结构，禁止医学诊断和确定性疾病判断。
- 服务端设置请求体限制、超时、输入长度限制、日志脱敏和通用错误响应。
- API 状态以“在线模式”或“演示模式”显示；回退时不阻断聊天体验。

## API 契约

`POST /api/chat` 接收消息数组和可选的数据上下文，返回：

```json
{
  "mode": "online",
  "message": {
    "content": "...",
    "emotion": "焦虑",
    "riskLevel": "中",
    "keywords": ["睡眠", "考试"]
  }
}
```

`GET /api/health` 只返回服务状态、模型是否已配置和当前模式，不泄露环境变量。上游返回非结构化文本时，服务端提供保守的字段推断和默认值。

## 测试与验收

- 单元测试：危机词检测、情绪分类、mock 回复结构、图表筛选派生、API 回退。
- 构建校验：TypeScript、Vite 客户端构建、服务端构建。
- API 校验：健康检查、普通消息、危机消息、上游失败回退。
- 浏览器校验：首页入口、六页导航、五种可视化、筛选联动、地图详情、数据库筛选、在线/演示聊天、危机提示。
- 视觉校验：桌面 1440px 与移动 390px 截图，检查空白画布、图表裁切、重叠、溢出、移动导航和咨询布局。

## 交付

工作区根目录包含完整源码、独立 mock 数据、`.env.example`、本地 `.env`、README 和测试。最终保持开发服务器运行并提供访问地址。若用户提供的 Anthropic 兼容接口无法通过实测，交付仍保证 mock 模式完整可用，并在 README 与最终说明中给出对应配置与排查步骤。
